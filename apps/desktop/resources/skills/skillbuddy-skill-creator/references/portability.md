# 跨 Agent 可移植性

## 兼容层级

将产物归入以下级别，并在交付时说明：

1. **完全兼容**：仅依赖通用指令、标准文件操作和包内资源。
2. **条件兼容**：依赖可安装的 CLI、运行时、环境变量或 MCP。
3. **需要适配**：正文引用宿主专属工具、权限模型、子 agent 或 UI 能力。
4. **平台专属**：核心目标依赖某个 agent 独有能力，无法合理降级。

## 通用核心

- 使用 `SKILL.md` 的 `name` 和 `description` 作为最小公共元数据。
- 使用相对路径引用包内 `scripts/`、`references/` 和 `assets/`。
- 用能力描述代替宿主工具名称，例如“读取文件”而不是绑定某个具体 Read 工具。
- 将工具选择留给执行 agent，除非特定工具是工作流不可替代的组成部分。
- 明确输入、输出、失败处理和停止条件，不依赖宿主默认行为。

## 依赖处理

- 对 CLI 依赖写明可执行文件名、最低能力和缺失时的处理方式。
- 对 MCP 依赖写明服务标识、所需工具和授权前提，不写入凭据。
- 对语言运行时依赖写明版本或标准库要求。
- 对网络、浏览器、GUI 或系统权限依赖明确标记，不假设所有 agent 默认拥有。
- 提供合理降级路径；无法降级时立即说明限制。

## 宿主专属能力

以下内容不得无条件写入通用流程：

- `$skill`、斜杠命令或 GUI Skill 标签等调用语法。
- 特定 agent 的工具名称或结构化参数。
- 特定的 subagent、Todo、Plan、AskUser 或文件呈现工具。
- 某个平台的插件清单、UI 元数据或安装目录。
- 依赖宿主自动授权的写入、网络或命令执行操作。

需要这些能力时，将其隔离到平台参考文件中，并在通用流程中提供能力检测与回退。

## 检查清单

- 名称和 description 能否被所有目标 agent 理解。
- 正文是否包含平台名称、绝对目录或专属调用语法。
- 所有包内相对路径是否真实存在。
- 脚本是否依赖未声明的软件、网络或权限。
- MCP 和环境变量依赖是否明确但未泄露值。
- 缺少高级能力时是否仍能完成核心任务。
- 安装到其他 agent 后是否会产生无效或误导性的触发。
