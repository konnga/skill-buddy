# 竞品分析

> 版本：v0.1 ｜ 日期：2026-08-06

## 竞品一：xingkongliang/skills-manager

调研日期 2026-08-06。3.5k stars / 312 forks / 149 open issues，v1.29+，
活跃维护，macOS 签名公证，MIT 协议，单维护者社区项目。

### 产品概况

- **形态**：Tauri 2 + Rust + React 19 桌面应用 + CLI（共享 Rust core 与 SQLite）
- **模式**：中央技能库 `~/.skills-manager` → 软链接/复制分发到各工具目录
- **平台**：内置 16 个（Cursor / Claude Code / Codex / Grok / OpenCode / Amp /
  Kilo Code / Roo Code / Goose / Gemini CLI / GitHub Copilot / Windsurf /
  TRAE IDE / Antigravity / Clawdbot / Droid）+ 自定义工具
- **亮点功能**：Preset（技能分组批量激活）、三类工作区（全局/项目/关联）、
  基于 Git 私仓的多设备备份（按技能粒度合并 + 快照恢复）、skills.sh 市场接入、
  令牌存系统钥匙串

### 重要认知修正

它用软链接/复制即可完成多端分发，说明各平台 skills 格式已事实趋同
（SKILL.md 成为准标准）。**「格式转换」的痛点比我们最初假设的轻**，
真正的痛点是：统一视图、可靠分发、编辑闭环、团队共享。

### 弱点（附证据）

1. **核心机制可靠性差**（issues 最集中的抱怨）
   - 三态架构（SQLite / 中央库 / 工具目录）状态漂移：#347 工作区技能重复、
     #349 中央仓库更新看不到
   - #339 缓存体积失控；软链接在 Windows 受限，链接/复制双模式并存加倍复杂度
2. **16 平台长尾维护失血**：#345 qoder 识别不了、#343 WorkBuddy 识别不到。
   检测绑定写死的第三方目录约定，平台一变就坏一个
3. **只是分发器，不是管理平台**
   - 无编辑能力（#348 用户在求）——创作修改还得离开工具，不闭环
   - 管理范围窄：用户在要 MCP / plugins / agents 管理（#353）
   - 无团队/企业层：同步=个人 Git 私仓备份，无团队空间/权限/审核/下发/审计；
     本地架构（SQLite + 中央库）长出服务端形态需伤筋动骨
   - WSL 不支持（#352），企业 Windows 用户大量在 WSL
4. **UI 概念混乱**（结构性原因）
   - 概念模型堆叠：中央库 × 三类工作区 × Preset × 两种分发模式 × Git 同步 ×
     16 平台角标，≥6 个正交概念相乘，无统一心智模型
   - 界面围绕内部机制（工作区→Agent→激活状态）组织，用户必须先理解
     分发原理才会操作；而用户的真实心智模型是「我的 skills 装在哪、
     还要装到哪」
5. **可持续性风险**：单维护者 + 149 open issues；v1.29.0 macOS 构建产物
   整体缺失（#356）；Rust 栈抬高社区贡献门槛；无商业模式支撑长期维护

## 我们的差异化策略（已定）

**基本功能对齐 + 三个差异化支点：可靠性、UI/交互、团队协作。**

| 竞品的问题 | 我们的对策 |
|---|---|
| 三态架构状态漂移 | **工具目录即真实来源**（single source of truth），不建中央库 |
| 16 平台长尾失血 | 3-5 平台做到「永远识别得到」+ 自定义路径兜底 |
| 只分发不闭环 | 创作 / 编辑 / 分发 / 同步一体 |
| UI 概念混乱 | **按 skill 聚合的单一视图**，徽标即多端状态，零内部概念外露 |
| 无团队/企业层 | **Phase 2 团队协作为核心主攻**（registry + 团队空间），架构从第一天为此设计 |

## 其他相关生态（待展开调研）

- **skills.sh**：skills 市场/目录站，竞品已接入。对我们是潜在的导入来源
  （兼容其安装协议可蹭生态），Phase 2 registry 的参照物
- 各 agent 官方的 marketplace / plugin 机制（Claude Code plugins 等）：
  可能吸收部分需求，需持续跟踪

## 对齐进展（2026-08-12）

- Preset 已支持实时状态、按当前 Agent / 项目 / 来源筛选整组启停，以及严格版本化
  JSON 导入导出；Agent 目录仍是唯一真实来源。
- 市场已接入 skills.sh、SkillHub 和 GitHub。
- Git 多设备备份已支持用户级 Skills + Preset 的可审计快照、普通 push、恢复预览
  和目标 Agent 选择；不备份本机路径、运行状态、MCP 配置或密钥。
- 仍待竞品对齐的主要工程项是多平台真机兼容矩阵和正式发布验收；团队/企业侧
  的 SSO、Web 控制台、审批流属于后续产品阶段。
